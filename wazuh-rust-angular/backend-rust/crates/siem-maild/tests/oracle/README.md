# wazuh-maild oracle

Diffs the Rust port against the real C maild sources (Wazuh 4.14.7).

* `run.sh` (needs root in WSL: the fake SMTP server listens on 127.0.0.1:25, the port
  C hard-codes): `harness.c` and `examples/mail_oracle.rs` run the same commands
  (config + `getconfig`, alerts.json / alerts.log -> e-mail text and granular
  matching, `OS_Sendmail`, `OS_Sendsms`, `OS_SendCustomEmail`, the daily report);
  stdout, log lines and every SMTP byte received (Date masked) are compared.
* `loop.sh`: the real daemons (`c_maild` built from maild.c, and `wazuh-maild`)
  on the same alert timeline (`timeline.py`); the e-mails received are compared.

Build: `bash build.sh` (C, as the normal user), then
`CARGO_TARGET_DIR=$HOME/tgt-linux cargo build -p siem-maild --example mail_oracle --bin wazuh-maild`;
scenarios are generated by `gen_scenarios.py`.

2026-10-16: run.sh 12/12 scenarios identical; loop.sh: the same e-mails, except
that C sent two of them twice. Its forked child's `exit()` flushes the
inherited `FILE*` of alerts.json and glibc moves the shared file offset back,
so the parent reads those lines again (a C bug: duplicate notifications).
The Rust port uses threads and reads each alert once.
