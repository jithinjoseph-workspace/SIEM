# siem-wdb

Port of Wazuh 4.14.7's `wazuh-db` (`src/wazuh_db/`) and the wazuh-db part of
the router's HTTP API.

## Layout (`src/wdb/`)

| Module | Wazuh source |
| --- | --- |
| `mod.rs` | `wdb.c`, `wdb_pool.c`, `wdb_metadata.c`, `wdb_upgrade.c` |
| `parser.rs`, `parser_agent.rs`, `parser_global.rs` | `wdb_parser.c` |
| `global.rs`, `integrity.rs` | `wdb_global.c`, `wdb_integrity.c` |
| `fim.rs`, `syscollector.rs`, `sca.rs`, `agentdb.rs`, `delta.rs` | `wdb_fim.c`, `wdb_scan_info.c`, `wdb_syscollector.c`, `wdb_sca.c`, `wdb_rootcheck.c`, `wdb_ciscat.c`, `wdb_agents.c`, `wdb_delta_event.c` |
| `task.rs` | `wdb_task.c`, `wdb_com.c` |
| `state.rs`, `stmts.rs`, `tables.rs`, `schema.rs` (generated by `tools/gen_*.py`) | `wdb_state.c`, `wdb.h`, the `TABLE_*` maps, `schema_*.sql` |
| `config.rs` | `config/wazuh_db-config.c` and the `wazuh_db.*` internal options |
| `daemon.rs` + `src/bin/wazuh-db.rs` | `main.c` (dealer, worker pool on an epoll queue, gc, upgrade and backup threads) |
| `http.rs`, `httplib.rs` | `router.cpp`'s API part, `router/src/wazuh-db/*`, cpp-httplib 0.14.2's server |

SQLite is 3.50.4 (`siem-sqlite`), JSON is cJSON-compatible (`siem-cjson`) and
nlohmann-compatible for the HTTP bodies (`siem-njson`), gzip backups go
through the bundled zlib (`libz-sys`, static). Router publications go
through `siem-router`. The daemon, the HTTP API and the router are Linux
only, like the C.

Process services (logging, clock, router, peer socket, local time) go
through the `WdbEnv` trait, so the tests pin and capture them.

## Verification

The C library is the oracle (`tools/oracle/`, built in WSL Ubuntu 20.04):

```sh
# once: Wazuh's src, SQLite 3.50.4, cJSON and zlib from deps/54
ORACLE_TOOLS=$PWD/tools/oracle bash tools/oracle/setup.sh <wazuh>/src <sqlite> <cJSON> <zlib>
cd ~/wdb_oracle && bash build.sh && bash http_build.sh <wazuh>/src   # needs ~/wazuh_deps (cpp-httplib, nlohmann)
mkdir -p home hhome
```

* `tests/wdb_oracle.rs`: the request stream (scenarios covering every
  command, plus seeded mutations) through the Rust library and through
  `wdb_oracle`; answers, streamed messages, router publications, logs and a
  dump of every database file (rows, gzip backups by content hash) must be
  identical. `SIEM_WDB_ORACLE="env TZ=UTC ~/wdb_oracle/wdb_oracle ~/wdb_oracle/home"`,
  `SIEM_WDB_FUZZ`, `SIEM_WDB_SEED`, `SIEM_WDB_KEEP`. The backup scenario
  runs on Linux only (the snapshot names contain `:`).
* `tests/http_oracle.rs` (Linux): raw HTTP exchanges with the real
  router/httplib/nlohmann code over the real wazuh-db library
  (`SIEM_HTTP_ORACLE="env TZ=UTC ~/wdb_oracle/http_oracle ~/wdb_oracle/hhome"`,
  `SIEM_HTTP_FUZZ`, `SIEM_HTTP_SEED`, `SIEM_HTTP_KEEP`).
* `tests/daemon_e2e.rs` (Linux): the daemon threads, the wire protocol, the
  HTTP API and the router delivery.

Known differences, kept out of the oracle on purpose (the harnesses say why):
`errno` left over by earlier requests of a worker thread
(`wdb_remove_multiple_agents`), the uninitialized `agent[]` key of
`wazuhdb remove` with an invalid first id, the real-time file mtimes the
backup selection reads, and request buffers holding older requests.
